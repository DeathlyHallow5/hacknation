# Статус: что работает, а что нет

> Снимок на **2026-11-21, вечер**. Всё ниже проверено на живом стеке (`docker compose --profile lab up`)
> на Windows 11 + Docker Desktop, если не сказано иное. Подробности архитектуры — `PROJECT.md`,
> контекст и ТЗ — `HANDOFF.md`, сценарий видео — `docs/DEMO-VIDEO.md`.

## Как запустить

```bash
cp .env.example .env
# ASI_DATA_KEY: openssl rand -base64 32;  ASI_ADMIN_PASSWORD: >= 12 символов
docker compose --profile lab up --build -d
```

- Дашборд: http://localhost:3000 — вход `admin` / пароль из `ASI_ADMIN_PASSWORD`.
- API ядра: http://localhost:8000/api (скрипты) и http://localhost:8000/api/v1 (контракт дашборда).
- Сканы лабы: `scripts/diff-demo.sh` (4 прогона с изменениями, ~2.5 мин) или `scripts/lab-scan.sh`.

## ⚠️ Работает частично / с оговорками

- **Окна по времени.** Есть окна по длительности с паузой и продолжением с чекпоинта. Окон по часам
  (`HH:MM`, часовой пояс, дни недели — F-20) нет: дашборд показывает фиксированное окно 00:00–23:59.
- **Исключённые цели** не попадают в новые прогоны, но исключение одного IP *внутри* сканируемого CIDR
  этот IP из CIDR не вычитает.
- **Находки** выводятся из последнего прогона: админки, staging, «опасные» порты. Своих сигнатур нет,
  CMS/TLS-проблемы/заголовки безопасности отдельными находками не считаются.
- **Ограничение входа по IP** при входе через UI видит адрес контейнера `web`, а не браузера: 20 ошибок за
  15 минут от любых пользователей UI заблокируют вход через UI для всех (лимит на логин работает как надо).
- Уведомление после «Dodaj cele» говорит, что цели попадут в ближайшее сканирование, — сами по себе они
  ни к какому скану не привязываются (скан создаётся через API со своим списком целей).

## ❌ Не работает / не сделано

**Фронтенд — страниц нет (ссылки в меню ведут на 404):** Znaleziska (`/findings`), Zmiany (`/changes`),
Zasoby (`/assets`), Skanowania (`/scans`, `/scans/new`), Sygnatury, все страницы Administracja
(пользователи, роли, интеграции, журнал, настройки), Deklaracja dostępności. Есть только вход, Pulpit и Zakresy.

**Нет запуска сканов из UI.** Скан создаётся и запускается через API (`POST /api/scans`) или скрипты.
В `/api/v1` нет: управления сканами (создание, пауза, продолжение, отмена, оценка, события SSE),
профилей и расписаний, хостов/сервисов, диффов, сигнатур, пользователей/ролей, интеграций, настроек.

**Бэкенд:**
- Кастомные сигнатуры (10% оценки) — не начато, ТЗ в HANDOFF §9.2.
- Импорт **результатов** сканов (JSON/CSV/nmap XML) — нет; импорт/экспорт **целей** и экспорт находок — есть.
- DefectDojo — кнопка в UI честно отвечает «ещё недоступно» (501); сырые выводы сканеров для него уже хранятся.
- Scope-политика (F-02), общий бюджет pps (F-11), пагинация `/api/runs/{id}/findings` (F-19).

**Проверки целостности прогонов.** На отдельном PostgreSQL 17 прошёл интеграционный тест T-07–T-10.
Он вызывает рабочий обработчик прогонов и проверяет сохранённые результаты после отказа инструмента,
удаления цели, возобновления и отмены. Для отмены тест вызывает обработчик API напрямую. Для проверки
снимка портов читает PostgreSQL после возобновления. Запуск из корня с `DATABASE_URL` одноразового
PostgreSQL и без naabu в PATH: `cargo test --manifest-path core/Cargo.toml run_integrity -- --ignored`.
Бенчмарк на 10 000 IP остаётся открытым.
