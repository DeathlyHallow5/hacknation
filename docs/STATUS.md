## ⚠️ С оговорками

- **Исключённые цели** не попадают в прогоны, но один IP, исключённый *внутри* сканируемого CIDR, из него не вычитается.
- **Ограничение входа по IP** через панель видит адрес контейнера `web`: 20 ошибок за 15 минут от любых
  пользователей заблокируют вход через UI для всех (лимит на конкретный логин работает как надо).
- **SYN-скан** (`compose.syn.yaml`) — экспериментальный: в первом замере пропустил открытые порты у 17 из 66 хостов.
- **Встроенные профили Szybki / Standardowy / Delikatny** (top-100/1000) сканируют только одобренные порты из своего
  top-N (по `nmap-services`); например, 6379 (redis) в top-100 не входит. Для лабы — **Laboratorium** (100 запросов/с),
  для 10 000+ адресов — **Duża sieć** (1000 запросов/с).
- **Бенчмарк** (`scripts/bench/`) требует сеть стенда в `ASI_ALLOWED_CIDRS`; проверки `scripts/e2e/` ходят через панель и `compose.api.yaml` не требуют.
- После смены сетей в `compose.yaml` на уже запущенном стеке Docker Desktop может подключить контейнер без
  DNS-имени сервиса (`db` не резолвится) — помогает `docker compose down` и снова `up`.
- Повторного запуска скана одной кнопкой в панели нет — запускается новый скан с теми же целями (дифф строится и так).

## ❌ Не сделано

- Ротация ключа шифрования (`POST /security/encryption/rotate` отвечает 501).
- Пакетный (а не по аргументам сканеров) лимит pps и проверки DNS-rebinding / редиректов — см. `deploy/SECURITY.md`.
- Пассивные источники (crt.sh, rDNS), корреляция версий с CVE.
