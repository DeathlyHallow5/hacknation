# Шум сканера: замер и чистка

> 2026-11-21. Как измеряли: `tcpdump` в сетевом пространстве контейнера `core` (без трафика к БД и API),
> один прогон скана через `/api/v1/scans`, плюс логи самих сканируемых сервисов за то же время.
> Стенды: лаба `172.30.0.0/28` (профиль «Szybki», top-100 портов; 5 живых адресов, 3 веб-сервера) и
> TestLab `quickstart` (Gitea, RabbitMQ, nginx; 5 портов на хосте Docker).

## Что было не так

| Проблема | Как выглядело у цели |
|---|---|
| **Сканер ходил в интернет** — naabu/httpx при каждом запуске проверяли обновления | DNS `api.pdtm.sh` + TLS к `65.109.43.133:443` — о скане узнаёт посторонний сервер |
| **nmap `-sV` запускал NSE-скрипты категории «version»** | `POST /sdk`, `GET /HNAP1`, `GET /evox/about`, `GET /nmaplowercheck…` с UA «Nmap Scripting Engine» — выглядит как перебор эксплойтов, nginx пишет `open() failed` |
| **httpx шёл на все открытые порты**, включая SSH, AMQP, БД | Gitea (SSH): `banner exchange: invalid format` ×6; RabbitMQ: `bad_header "GET / HT"` ×16; httpx ждал таймауты |
| **httpx маскировался под браузер** (случайный Firefox/Chrome) | анонимный трафик, не отличить от пользователя |
| **`-sV` с полным набором проб** | на неизвестном порту: `OPTIONS RTSP`, `OPTIONS sip:`, `GET /nice ports,/Trinity.txt.bak`… и не укладывался во время — 0 из 5 сервисов опознано |
| **`-sV` по объединению портов всех хостов** | каждый хост проверялся и на портах, открытых только у соседей |

## Что сделано (`core/src/pipeline.rs`, `core/Dockerfile`)

- `-duc` у naabu и httpx — никаких проверок обновлений; сканер говорит только с целями.
- NSE-скрипты категории «version» (44 шт.) не поставляются в образ; `-sV` делает только версионные пробы.
- `-sV --version-light` — только частые пробы.
- `-sV` по своим открытым портам каждого хоста (хосты сгруппированы по набору портов, не больше 32 запусков nmap на партию).
- httpx — только на порты, которые nmap определил как HTTP/TLS или не смог определить (имя, угаданное по таблице портов с уверенностью < 0,5, считается неопознанным). Если `-sV` упал — на все порты, как раньше.
- httpx с честным `User-Agent` из настроек (`scan_safety.user_agent`, по умолчанию `ASI/0.1 (…)`), `-random-agent=false`.

Проверено, что чистка не ухудшила обнаружение: сценарий TestLab «сервис исчез и вернулся» — 6/6,
`scripts/diff-demo.sh` находит новую админку (interest 3), unstable → inactive и возвращение Apache.

## Что осталось (известно, принято)

- **Два `GET /` на веб-сервер**: проба nmap без UA + httpx. Убрать пробу nmap можно только ценой опознания
  сервиса на нестандартных портах.
- **`/favicon.ico`** — нужен для хэша favicon; у сервера без иконки остаётся строка 404 в логе.
- **Pre-flight** (`nmap -sn` по 15 портам) частично дублирует naabu при пресете top-100 — до 15 лишних SYN на
  адрес; зато находит живые хосты без открытых портов из списка.
- **Сканер сканирует и сам себя**, если его адрес попал в диапазон (в лабе `172.30.0.2:8000`). Нужен
  авто-исключение своих адресов или scope-политика (F-02).
- **naabu `-retries 1`** на фильтрующих хостах удваивает попытки.

## Как повторить

```bash
docker run -d --name asi-pcap --net container:asi-core-1 --cap-add NET_RAW --cap-add NET_ADMIN \
  alpine:3.20 sh -c "apk add --no-cache tcpdump && sleep infinity"
docker exec -d asi-pcap tcpdump -i any -nn -U -s 0 -w /tmp/scan.pcap "not port 5432 and not port 8000"
# … один скан через UI/API …
docker exec asi-pcap pkill tcpdump
docker exec asi-pcap tcpdump -r /tmp/scan.pcap -nn "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0" | wc -l
docker exec asi-pcap tcpdump -r /tmp/scan.pcap -nn -A | grep -E "^(GET|POST|OPTIONS) |User-Agent:"
docker logs --since 5m asi-lab-nginx-1      # что увидел сервер
```
